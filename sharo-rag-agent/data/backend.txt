Project overview

Sharko (backend) is a FastAPI-based ML inference service that predicts shark habitat suitability around the Australian coastline (lon 110-160E, lat 9-46S) from real satellite ocean data, an official ocean forecast, and long-term climatology, then clusters the predicted hotspots into polygons and serves results as GeoJSON. It also exposes a simple RAG Q&A endpoint over local project documentation.



Core capabilities

- Species-specific habitat prediction: trained classifiers for Tiger Shark, Bull Shark, Great White Shark, and an "any shark" (all species pooled) model.

- Any-date prediction: the same API answers for a date in the past, the next ~9 days, up to 90 days ahead, or years into the future (e.g. 2030), by automatically switching between four data sources depending on how far ahead the date is (see "Prediction modes" below).

- Known-range gating: a species is only predicted as present within 500 km of where it has actually been recorded (2020-2026); this stops the model claiming habitat somewhere the species has never been seen just because the water conditions look similar.

- Clustering/hotspot detection: DBSCAN-based clustering of grid cells whose predicted suitability clears that species' tuned threshold, convex-hulled into polygons and returned as GeoJSON, in the same response shape the frontend has always consumed.

- RAG Q&A: local-embeddings-powered retrieval over project text files, with Gemini used only as the final LLM.



Repository layout (sharko-api)

- app.py: FastAPI app exposing health and prediction endpoints.

- au_predict.py: adapter that calls the Australia predictor and reshapes its output back into the API's existing response format, so no frontend changes were needed.

- au/: the Australia prediction package.

  - predictor.py: SharkoPredictor, the main prediction engine (see below).

  - climatology.py: typical ocean conditions per place and week of the year, used for far-future predictions.

  - features.py: shared ocean-feature extraction (satellite data, bathymetry, season), used identically at training and prediction time so the model always sees the same inputs it was trained on.

  - config.py: study-area bounds and shared settings.

  - models/: trained model bundles: any_model.joblib, bull_model.joblib, tiger_model.joblib, white_model.joblib (daily models), and the same four again under models/seasonal/ (long-range models trained on typical conditions).

  - data/climatology/clim_all.nc: typical conditions per 0.1-degree ocean cell and week of year (2020-2026 average).

  - data/forecast/forecast.nc and bias.nc: the latest Copernicus ocean forecast (about 9 days ahead), bias-corrected against satellite measurements.

  - data/ocean/bathymetry.nc: depth and distance to coast (NOAA ETOPO).

  - data/sharks_australia.csv: real 2020-2026 shark records, used for the known-range check.

- index.py, sharks.json, initial_zone_1_epsilon.geojson, prediction_points.parquet, and the original models/sst.joblib, ssh.joblib, chloro_model_log_independent_tuned.joblib, shark_presence.joblib: the original chained-regressor pipeline that covered the whole world. Still present in the repository for reference but no longer called by any live endpoint; superseded by au/ and au_predict.py.

- requirements.txt: runtime dependencies.



Prediction pipeline details (au/predictor.py)

- SharkoPredictor loads the four daily models, the four seasonal models, the climatology grid, the latest forecast (if present), and the real satellite archive (if present, used for past dates) once at startup.

- Prediction modes, chosen automatically from the requested date:

  - observed: the requested date has real satellite data on disk, so the daily models run on the real SST, sea level, currents and chlorophyll of that exact day.

  - forecast: the date falls within the roughly 9-day Copernicus ocean forecast window, so the daily models run on the bias-corrected forecast.

  - outlook: up to 90 days after the last known day, so the seasonal models run on typical conditions for that place and week, adjusted by how unusual the most recently known conditions were, with that adjustment fading out the further ahead the date is.

  - typical: any date further out (for example a 2030 date), so the seasonal models run on pure typical conditions for that place and week (2020-2026 average). A cooler-year/warmer-year range is also given, based on that week's usual year-to-year variability.

- Model inputs (10 features, deliberately excluding latitude/longitude so the model learns ocean conditions rather than "where the sensors or divers are"): sea temperature, temperature front (a spatial gradient), chlorophyll (log10), sea level anomaly, dynamic topography, current speed, depth, distance to coast, and season as sin/cos of day-of-year.

- Depth, distance to coast and season are always known exactly; only the six ocean variables change with the prediction mode.

- Known-range check: a nearest-neighbour lookup against each species' real 2020-2026 sightings; predictions more than 500 km from any recorded sighting of that species are forced to zero regardless of how suitable the water looks.



Public functions (au_predict.py)

- predict_presence_geojson(date): grid-predicts the "any shark" model across the whole Australian study area, thresholds it, clusters the surviving cells with DBSCAN, convex-hulls each cluster, and returns a GeoJSON FeatureCollection. Used by /predict/presence.

- predict_habitat_geojson(date, shark_name): the same, scoped to one species (Tiger Shark, Bull Shark or Great White Shark). Any other species name has no trained model and returns None, which the endpoint reports as "no valid clusters found", the same response the frontend already handles for an empty result.

- predict_location(lat, lon, date): single-point prediction, reshaped into {coordinates, date, predictions: {shark_presence, sst, ssh, chla}}. Used by /predict/location. Returns an error for points outside the Australian study area (110-160E / 9-46S) or with no ocean data, such as on land.



API (app.py)

- Framework: FastAPI with CORS enabled.

- Health:

  - GET /health: loads the legacy global models and reports status and model names.

  - GET /: basic root message.

- Prediction (response shapes are unchanged from the original API, so the existing frontend needed no changes):

  - GET /predict/presence?date=YYYY-MM-DD: general "any shark" habitat zones across Australian waters. Returns a PredictionResponse with presence_geojson_data.

  - GET /predict/habitat?date=YYYY-MM-DD&shark_name=Name: species-specific habitat zones. Tiger Shark, Bull Shark and Great White Shark have real models; any other species name returns no clusters. Returns habitat_geojson_data.

  - GET /predict/location?lat=...&lon=...&date=...: single-point prediction; returns numeric values for shark_presence, sst, ssh, chla. Returns HTTP 400 if the point falls outside Australian waters.

- RAG Q&A:

  - POST /ask: Question { context: list[tuple[str, str]], question: str }. Lazily loads the RAG chain on first call, then answers using the project text files described here plus Gemini as the final LLM.



Data and I/O

- Prediction inputs: real Copernicus Marine satellite data for past dates, the official Copernicus ocean forecast for the next ~9 days, and a precomputed climatology of typical conditions for anything further ahead, plus NOAA bathymetry (depth, distance to coast) and real 2020-2026 shark records for the known-range check.

- Outputs: GeoJSON FeatureCollections of cluster polygons for the presence/habitat endpoints, or a numeric prediction with an ocean-conditions breakdown for the location endpoint.



Dependencies and considerations

- ML and data science: numpy, pandas, scikit-learn, joblib, lightgbm, scipy.

- Ocean data: xarray, netCDF4, for reading the climatology, forecast and bathymetry NetCDF files.

- Geospatial: shapely, used for the convex-hull clustering step; geopandas, pyproj, fiona and rtree are only used by the legacy global pipeline and are unused by the live endpoints.

- API: fastapi, uvicorn, pydantic.

- RAG: langchain, langchain-community, langchain-huggingface, sentence-transformers, chromadb, python-dotenv, langchain-google-genai (Gemini).

- The study area is fixed to Australian waters: lon 110-160E, lat 9-46S. Requests outside that box return no data.



Typical flows

- Presence map: pick a date, the predictor scores the "any shark" model across the whole Australia grid using whichever data source fits that date (observed, forecast, outlook or typical), cells above the model's threshold are clustered into polygons, and GeoJSON is returned.

- Species habitat map: the same, scoped to one species' model and its own threshold. Only Tiger Shark, Bull Shark and Great White Shark currently have a trained model, in addition to the pooled "any shark" model.



Limitations and assumptions

- Only four species have real trained models today: Tiger Shark, Bull Shark, Great White Shark, and the pooled "any shark" model. Every other species previously listed for the worldwide version has no dedicated Australia model and returns no results.

- Predictions are confined to Australian coastal waters; a location or clustering request for anywhere else returns no data.

- The forecast data needs to be refreshed roughly daily to stay within its ~9-day window. If it goes stale, dates that would have used "forecast" mode fall back automatically to the climatology-based "outlook" or "typical" modes instead, so the API keeps working, just with a slightly lower-confidence input source.

- RAG uses local embeddings but still requires a valid Google Gemini key for the final LLM call.



Deployment

- Install from requirements.txt.

- Start: python app.py (Uvicorn on 0.0.0.0:8000; the Hugging Face Space runs it on port 7860 via Docker).

- Health check: GET /health.

- Example predictions:

  - GET /predict/presence?date=2030-01-15

  - GET /predict/habitat?date=2030-01-15&shark_name=Tiger%20Shark

  - GET /predict/location?lat=-33.9&lon=151.3&date=2030-01-15

- RAG: POST /ask with JSON body { "context": [["q1", "a1"]], "question": "..." }.
